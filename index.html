01 / 先把方案讲明白

三条任务路径，
讲清枝木处理场景。

建设一个总览页，分别通往清场、自用薪柴、原木制材；让用户按已有木料和工具进入需要的步骤。下文把本机数据、飞书原方案与具体页面内容一一对应。

先记住这一句话

保留“清场、薪柴、制材”三条路；
让用户从自己正在做的那一步进入。

飞书已有这三个去向，也已有“已有工具可跳过”的思路。这次重点是把中间的判断讲清楚：有没有主机、木料到了哪一步、工具负责什么动作、哪些组件仍需核对。

建设顺序依据内容依赖与说明完整性安排；三个去向并列，不按不同口径的估值排市场名次。

去向 A / 清场

我只想把落地枝木清走

先区分有无适配主机；按细枝、木段、长原木安排集中与转移，再讲清当地处置怎么查。可保留的木料再转到另两条路。

去向 B / 自用薪柴

我想把木料变成可储存的柴

长原木、已截木段、已劈好薪柴分别进入。只经历需要的定位、截段、劈分、转运、储存步骤。

去向 C / 原木制材

我想把原木保留为板坯

先看制材系统构成，再按完整配齐或单件补购核对。首刀导轨、制材架与链锯各有作用；板坯还有后续处理。

02 / 数据该怎么看

有数值支撑，也要读懂数值在说什么。

“有人搜这个词”“一个主题有估值”“监测了这个问题”，各自能支持的判断不同。

关键词：用来判断具体表达与内容入口

electric log splitter · 8,100
意为该英文词在US的估算月搜索量。它支持把“电动劈柴器如何选择”纳入比较内容。

它不能直接告诉我们某款商品能获得多少访问，也不能用近义词的量简单相加。

提示词：用来发现用户需要解释的问题

does firewood need to be covered
可译为“薪柴需要覆盖吗？”附带的 34,570 来自本记录的主题/模型字段，不是这一个问题的搜索量。

它支持补“遮盖与通风如何一起考虑”，不支持写成“此问句每月有34,570访问”。

再看两种容易混淆的证据

主题表 volume：例如“Firewood Storage Solutions”是40,428，这是US主题量估值，原文件没有明确月单位。它更宽泛，不能和某一个关键词比较后算占比。

Peec问法：用于监测AI回答；配置重复不等于消费者人数。没有流量估值就明确写“未提供流量估值”。

同问句不同模型：“Can I learn to mill my own lumber at home?”在Gemini记录附带11，在AI Mode记录附带740。两条是不同记录的主题/模型值，不相加，也不把较大值当单问句月量。

原词 / 问句→用户想解决的问题→需要补的解释→页面上的模块

后面的每条发现都按这个顺序展开。原字段与原文件定位可就近展开，数字只在原口径内解释。
